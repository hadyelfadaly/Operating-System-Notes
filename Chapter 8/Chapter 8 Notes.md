# Background

- Program must be brought (from disk) into memory and placed within a process for it to be run because main memory and registers are only storage CPU can access directly
- Memory unit only sees a stream of addresses + requests, The memory hardware does NOT understand programs or variables.
    - Read request + address
    - Write request + address + data
    - Example: We wan to calculate z = x + y
        1. CPU reads x from RAM and put it into register r1
        2. CPU reads x from RAM and put it into register r2
        3. ALU calculates z = r1 = r2 and stores it in register r3
        4. CPU writes Z into RAM if it wants to save it
- Register Access usually takes 1 clock cycle or less (They are extremely fast), this is why:
    - CPU instructions always operate on registers
    - Data must be loaded from memory → register → CPU
- Main memory can take many cycles, causing a stall (A stall occurs when the CPU waits for data from main memory), RAM is much slower than registers.
- Cache sits between main memory and CPU registers (faster than ram slower than registers), so it reduces stall and Provide fast access to frequently used data
- Protection of memory required to ensure correct operation, The OS must prevent a process from accessing memory that it does not own.

# Base and Limit Registers

They are a hardware protection mechanism used in contiguous memory allocation.

-  Base register:
    - Holds the starting physical address of the process in memory
    - Think of it as:   _“Your memory starts here”_
-  Limit register:
    - Holds the **size (length)** of the process’s memory
    - Think of it as:   _“You are allowed this much memory”_
- When a process runs in user mode, every memory access is checked by the CPU to be sure it is between base and limit for that user 
- Rule: base <= address < base + limit
    - if address is inside this range -> allow access, else The CPU generates a trap to the operating system due to illegal memory access.

# Address Binding

- **Logical address** – generated by the CPU; also referred to as virtual address.
- **Physical address** – address seen by memory unit.

**Address binding** = mapping addresses from one form to another during a program’s life, How a program’s addresses are converted from what the programmer writes → to actual memory locations in RAM.

- Relocation support is hardware and/or OS support that allows a program to be loaded into any memory location, not just address 0.
- Programs start on disk, they wait in an input queue ready to be brought into memory to execute.
    - If there is no relocation support -> Every program assumes it starts at address 0, and that's a problem that only one program, can be at 0 at a time.
- How can we fix this?
    - By using address binding / relocation.
    - Programs use relative (logical) addresses and Actual physical location is decided later
- Addresses represented in different ways at different stages of a program’s life
    1.  Source code addresses → symbolic (count, sum, ...) no numbers yet
    2. Compiled code addresses bind to relocatable addresses (relative not absolute, can be placed anywhere in memory)
    3. Linker or loader will bind relocatable addresses to absolute addresses (real RAM address)
- In Summary: Source Code (Symbolic) -> Compiled Code (Logical Address) -> Physical Address
- Programs Initially start at disk and get compiled there and then loaded to RAM (Load Time) Then to CPU (Execution time), In Summary: Disk (Compile Time) ->(Load Time) RAM -> (Execution Time) CPU, So the physical address must be determined at one of this stages.
-  Address binding of instructions and data to memory addresses can happen at three different stages: 
    -  **Compile time**: If memory location known a priori, absolute code can be generated, but Must recompile code if starting location changes. (Absolute Address)
    - **Load time**: must generate relocatable code if memory location is not known at compile time. (Relocatable Address)
    - **Execution time**: Binding delayed until run time if the process can be moved during its execution from one memory segment to another (Happens in RAM), Need hardware support for address maps (e.g., base and limit registers, MMU) (Logical -> Physical address)
- Relocatable Address Generated by Compiler/ Loader /OS, while Logical Address Generated by CPU, Both are the same concept tho.

 - Logical and physical addresses are the same in compile-time and load-time address-binding schemes; logical (virtual) and physical addresses differ in execution-time address-binding scheme.
 - **Logical address space** is the set of all logical addresses generated by a program
 - **Physical address space** is the set of all physical addresses generated by a program
# Memory-Management Unit (MMU)

Hardware device that at run time maps logical (virtual) to physical address.

- Base Register now called **Relocation Register**
- User program deals with logical addresses; it never sees the real physical addresses.
- Execution-time binding occurs when reference is made to location in memory
- Routine (Function or program) is not loaded until it is called
    - Better memory-space utilization; unused routine is never loaded
    - All routines kept on disk in relocatable load format (means it location in RAM not fixed as it may change through memory segments)
    - Useful when large amounts of code are needed to handle infrequently occurring cases (as we will only load the part we need)
    - No special support from the operating system is required as it is Implemented through program design but OS can help by providing libraries to implement dynamic loading (loading only what we need)
- Physical Address = base + logical address

# Dynamic Linking

- **Static linking** – system libraries combined by the loader into the binary program image.
- **Dynamic linking** – linking of system libraries postponed until execution time. 
- Example:
    - If we imported a library in our program with 10 function but we only need 3
        - Static linking imports all 10 into executable compiled file, which isn't efficient and lets say a new version of the library is out there we have to recompile
        - Dynamic Linking Imports only the needed functions in execution time, and it will also used the latest version always.
- **Stub**: A small piece of code, and a tiny placeholder inside the program.
- Stub Replaces itself with the address of the routine, and executes the routine.
    1. Program calls a library function
    2. Stub runs instead and asks the OS where is the real function
    3. OS Gives the real memory address
    4. Stub saves the address and jumps to it
    5. Next time it goes directly to the real function, so its only one-time lookup
- Dynamic linking is particularly useful for libraries, because in dynamic linking the same library is used once while in static linking you have to make a library copy for each process. (This system is also known as shared libraries)

# Swapping 

- Swapping processes is used when we want to load process from disk to memory but there is no space in memory so we swap with the least priority process.
- A process can be swapped temporarily out of memory to a backing store, and then brought back into memory for continued execution as Total physical memory space of processes can exceed physical memory
- **Backing store** – fast disk large enough to accommodate copies of all memory images for all users; must provide direct access to these memory images. (copy the memory content (image) of the process we going to swap with into disk.)
- **Roll out, roll in**  – swapping variant used for priority-based scheduling algorithms; lower priority process is swapped out (Roll Out) so higher-priority process can be loaded and executed (Roll In). (Ensures important processes don't wait behind weak ones)
![Pasted image 20260101165352.png](./Imgs/Pasted%20image%2020260101165352.png)

- Swap time = data transfer time, Directly proportional to the amount of memory swapped.
    - More memory = More time = Slower System
    - Context Switching becomes very slow. 
- That's why its better to avoid swapping.
- System maintains a ready queue consisting of all ready-to-run processes whose memory images are on backing store or in memory. (So processes in ready queue might be on disk or in memory)
- swapped out process need to swap back in to same physical addresses? Depends on address binding method.
    - Compile time: yes as the process absolute address is already determined.
    - Load time: yes as its address is fixed after loading
    - Execution time: No MMU binds dynamically as processes can move in RAM -> not fixed.
- Modified versions of swapping are found on many systems
    -  Swapping normally disabled and started only if more than threshold amount of memory allocated Then disabled again once memory demand reduced below threshold
- Context Switching Includes Swapping, That's why Context switch time can then be very high.
- Time Context Switch = Size / Rate 
- Can reduce time through decreasing size of memory swapped – by knowing how much memory really being used, by specified functions or as parameters to functions
- Other constraints as well on swapping: 
    - If there is a process that has a pending I/O operation or requested data, it shouldn't be swapped or the I/O data might go to the wrong process or transfer I/O data to kernel space, then to process that requested data when it comes back to main memory (double buffering), but that's why its overhead because we copied data 2 times.
-  Swapping not supported on mobile systems, Instead use other methods to free memory if low space
    - Android Terminates apps if low free memory
    - IOS asks apps to voluntarily release allocated memory if not terminates like android

# Contiguous Allocation

**Contiguous memory allocation** is a memory management scheme in which each process is allocated a single continuous block of physical memory.

- Main memory must accommodate both OS and various user processes, Must to allocate main memory in most efficient way
- Main memory usually divided into two partitions:
    1. Resident operating system, usually held in low memory with interrupt vector.
    2. User processes then held in high memory
- Relocation registers (base registers) used to protect user processes from each other, and from changing operating-system code and data, as they contain value of the smallest physical address, Limit register contains range of logical addresses each logical address must be less than the limit register.
- MMU maps logical address dynamically by adding the value in the base register.
- As part of context switch, dispatcher loads base and limit registers values of a process under execution
- This scheme provides an effective way to allow operating system’s size to change dynamically. Because we might not need all OS Services. (Suitable if an OS service is not commonly used). Such services code is called transient code (**Transient code** is code that is loaded into memory only when it is needed and removed when it is no longer needed.)
- Memory is divide into several partitions – multiple-partition method:
    - Variable-partition sizes for efficiency (sized to a given process’ needs)
    - **Hole** – block of available memory; holes of various size are scattered throughout memory
    - When a process arrives, it is allocated memory from a hole large enough to accommodate it
    - Process exiting frees its partition and adjacent free partitions combined into one hole instead of several ones
    - Operating system maintains information about:
        -  allocated partitions
        - free partitions (holes)
     - Degree of multiprogramming limited by number of partitions (number of processes in memory)

## Dynamic Storage-Allocation Problem

How to satisfy a request of size n from a list of free holes?

- **First-fit**: Allocate the first hole that is big enough
- **Best-fit**: Allocate the smallest hole that is big enough; must search entire list, unless ordered by size, this method produces the smallest leftover hole
- **Worst-fit**: Allocate the largest hole; must also search entire list

First-fit and best-fit better than worst-fit in terms of speed and storage utilization

## Fragmentation

- **External Fragmentation** – total memory space is enough to satisfy a request, but it is not contiguous.
    - Storage is fragmented into a large number of small holes.
    - First-fit and best-fit strategies for memory allocation suffer from external fragmentation
    - First fit analysis reveals that given N blocks allocated, 1/2 N blocks lost to fragmentation, 1/3 of memory may be unusable.
    - Example: A process of 50 KB waiting to be loaded to memory but there is no enough hole for it but there are 30 and 20 KBs holes that sums to 50 but they are not contiguous and the process cant be divided.
- **Internal Fragmentation** – allocated memory may be slightly larger than requested memory; this size difference is memory internal to a partition, but not being used.
    - Example: Requested memory is 30 KB and allocated memory is 40 KB, There is 10 KB unused.
- Reduce external fragmentation by **compaction** (Moving Processes)
    -  Shuffle memory contents to place all free memory together in one large block.
    - Compaction is possible only if relocation is dynamic, and is done at execution time (so we can physical addresses as we can't change it in Compile time and load time), Relocation requires just moving the process and then changing the base register to reflect the new base address
    - I/O Problem as a process who requested data might move from its place causing another process to get this data. Solutions:
        - Lock job in memory while it is involved in I/O
        - Do I/O only into OS buffers (double buffering)
- backing store has same fragmentation problems

# Segmentation

**Segmentation** allows a program to be viewed as a collection of logical segments, where each segment has its own base and limit, supporting the user’s view of memory.
![Pasted image 20260101202023.png](./Imgs/Pasted%20image%2020260101202023.png)

- Logical address consists of a two tuple: <segment-number, offset>
- A Segment table is used to map the two dimensional logical addresses of each process into one-dimensional physical addresses
    - Each entry in the segment table has:
        - **base** – contains the starting physical address where the segment reside in memory
        - **limit** – specifies the length of the segment
- Physical address = base[s] + offset (s -> segment number, d -> offset)
![Pasted image 20260101202813.png](./Imgs/Pasted%20image%2020260101202813.png)

- Hardware support:
    - **Segment-table base register** (STBR) points to the segment table’s location in memory
    - **Segment-table length register** (STLR) indicates number of segments used by a process; Segment number s is legal if s < STLR
- Protection:
    - With each entry in segment table associate:
        - validation bit = 0 -> illegal segment 
        - read/write/execute privileges
- Protection bits associated with segments
- code sharing occurs at segment level (Multiple Segments From different Segment Tables might point to the same segment physical address (multiple processes share a function))
- Since segments vary in length, memory allocation is a dynamic storage-allocation problem similar problem to external fragmentation

# Paging

- Divide logical memory into blocks of same size called pages. Example: a process of 50 KB divided into five 10 KBs Pages.
- Physical address space of a process can be noncontiguous; process is allocated physical memory whenever the latter is available
    -  Avoids external fragmentation
    - Avoids problem of varying sized memory chunks
- Divide physical memory into fixed-sized blocks called frames
    - Size is power of 2, Normally, between 512 bytes and 16 Mbytes
- Keep track of all free frames
- To execute a program of size N pages, need to find N free frames and load program
- Set up a page table to translate logical addresses to physical addresses and then Map the corresponding physical frame for each logical page
- Backing store likewise split into pages
- Still have Internal fragmentation, Last frame allocated may not be completely full. Example: we decided that each page/frame is 8 KB and Process is 50 KB, so 50/8 = 6.25 pages, pages can't be decimal so we make 7 pages each one is 8 KB except last page is 2 KB, So there will be one frame that only takes 2 KB not the whole 8 KB =  Internal fragmentation.
- Address generated by CPU is divided into: 
    - **Page number** (p) – used as an index into a page table which contains base address of each page in physical memory
    - **Page offset** (d) – combined with base address to define the physical memory address that is sent to the memory unit
    -  Logical address space is 2^m and page size is 2^n , n = page offset, m-n = page number.

## Implementation of Page Table

- If the page table is reasonably small dedicated registers are used for implementing the page table.
- Most computers allow the page table to be very large; therefore, the page table is kept in main memory
    - **Page-table base register** (PTBR) points to the page table
    - **Page-table length register** (PTLR) indicates size of the page table
- In the last scheme every data/instruction access requires two memory accesses, One for the page table and one for the data/instruction so it takes time, The two memory access problem can be solved using a special fast lookup memory cache called **translation look-aside buffer** (TLB)
     - Each entry in TLB consists of two parts: a page no. as a key and a corresponding frame value
     - An item is compared with all keys simultaneously
     - If a page number is not in the TLB (a TLB miss), its frame is added for faster access next time
     - Parallel search through the TLB not one entry by one.

## Effective Access Time (EAT)

Average Time to access memory considering hits and misses
- $\alpha$ = TLB hit ratio, $\varepsilon$ = TLB (associative) lookup time.
- $EAT = (1+\varepsilon)\alpha + (2+\varepsilon)(1-\alpha)$ = $2 + \varepsilon - \alpha$ 
- $(1+\varepsilon)\alpha$ -> 1 time unit for one lookup from TLB, $\varepsilon$ for TLB lookup time and $\alpha$ for hit ratio
- $(2+\varepsilon)(1-\alpha)$ -> $(2+\varepsilon)$ for the 2nd case of 2 time unit for lookups if not found in TLB, $(1-\alpha)$ not found in TLB ratio

## Memory Protection

 - Memory protection implemented by associating protection bit with each frame to indicate if read-only or read-write access is allowed
 - Valid-invalid bit attached to each entry in the page table:
    -  “valid” indicates that the associated page is in the process’ logical address space, and it is a legal page
    - “ invalid ” indicates that the page is not in the process’ logical address space
    - Any violations result in a trap to the kernel
    - Or use page-table length register (PTLR) instead

## Shared Pages

- A **re-entrant** program or code is code that can safely be executed by multiple processes or threads at the same time without interfering with each other
- **Shared code** - One copy of read-only (reentrant) code shared among processes
- **Private code and data** - Each process keeps a separate copy of the code and data and the pages can appear anywhere in the logical address space (flexible)

## Structure of the Page Table

- Memory structures for paging can get huge using straight-forward methods.
- Alternative Methods:

### Hierarchical Paging

- Break up the logical address space into multiple page tables, A simple technique is a two-level page table, We then page the page table
- If we have a 32-bit machine with 1 KB page size, 1 KB = 2^10 bits so 10 bits for offset and 22 for page number which will be divided into a 12-bit page number, a 10-bit page offset.

### Hashed Page Tables

- Common in address spaces > 32 bits
- The virtual page number is hashed into a page table, This page table contains a chain of elements hashing to the same location (linked list to solve collision)
- Each element contains:
    1. the virtual page number
    2. the value of the mapped page frame
    3. a pointer to the next element
- Virtual page numbers are compared in this chain searching for a match, When a match is found, the corresponding physical frame is extracted
![Pasted image 20260101232506.png](./Imgs/Pasted%20image%2020260101232506.png)

### Inverted Page Table

- Rather than each process having a page table and keeping track of all possible logical pages, track all physical pages
    - One entry for each real page (frame) of memory
    - Each entry consists of the virtual address of the page stored in that real memory location, with information about the process that owns that page
- Decreases memory needed to store each page table, but increases time needed to search the table when a page reference occurs, so we can use Use hash table to limit search to one, or at most a few, page-table entries and use TLB to accelerate access.
